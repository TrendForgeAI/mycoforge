# Cynefin Framework

**Kategorien:** problem-solving | **Rollen:** planner, architect, team-lead | **Tier:** 2
**Referenz:** Dave Snowden — IBM (1999)

## Core Concepts — 5 Domains

| Domain | Charakteristik | Vorgehen |
|--------|---------------|----------|
| **Clear** (vormals Simple) | Ursache-Wirkung offensichtlich | Sense → Categorize → Respond (Best Practices) |
| **Complicated** | Ursache-Wirkung analysierbar | Sense → Analyze → Respond (Good Practices) |
| **Complex** | Ursache-Wirkung erst im Nachhinein klar | Probe → Sense → Respond (Emergent Practices) |
| **Chaotic** | Keine Ursache-Wirkung erkennbar | Act → Sense → Respond (Novel Practices) |
| **Confused** | Domain unklar | Zerteilen in bekannte Domains |

**Gefahr der Complacency:** Clear-Domain kann plötzlich nach Chaotic kippen (Klippen-Effekt).

**Safe-to-fail Probes:** Im Complex-Domain kleine Experimente statt großer Pläne.

## Wann einsetzen

- Problemkomplexität einschätzen bevor man eine Lösungsstrategie wählt
- Agile vs. Waterfall Entscheidung: Complex → Agile, Complicated → Plan-driven
- Incident Response: Chaotic-Domain erkennen und handeln statt analysieren
- Neue Feature-Entscheidungen: Ist das ein bekanntes oder unbekanntes Problem?
