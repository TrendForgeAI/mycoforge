# Feynman Technique

**Kategorien:** problem-solving | **Rollen:** developer, educator | **Tier:** 1
**Referenz:** Richard Feynman — "If you can't explain it simply, you don't understand it well enough."

## Core Concepts

| Schritt | Aktion |
|---------|--------|
| **1. Konzept wählen** | Ein Thema das verstanden werden soll |
| **2. Einfach erklären** | In einfacher Sprache erklären als würde man es einem Kind erklären |
| **3. Lücken identifizieren** | Wo stockt die Erklärung? Das sind die Wissenslücken |
| **4. Zurück zur Quelle** | Lücken schließen, dann erneut einfach erklären |

**Kernprinzip:** Komplizierte Sprache und Fachjargon verbergen oft fehlendes Verständnis.

## Wann einsetzen

- Neues technisches Material aufnehmen (Architekturmuster, Algorithmen)
- Eigenes Verständnis validieren vor Code-Reviews oder Präsentationen
- Unklaren Code in einfachen Worten beschreiben (wie Rubber Duck Debugging)
- Dokumentation schreiben: wenn die Erklärung unklar ist, ist das Verständnis unklar

## Prompt Pattern

```
Erkläre [Konzept / Code / Architekturentscheidung] so,
als würdest du es jemandem ohne Vorkenntnisse erklären.
Wo wird die Erklärung unklar oder kompliziert?
```
