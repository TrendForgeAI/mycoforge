# User Story Mapping

**Kategorien:** requirements, strategic-planning | **Rollen:** planner, product-owner | **Tier:** 2
**Referenz:** Jeff Patton — *User Story Mapping* (2014)

## Core Concepts

| Begriff | Bedeutung |
|---------|-----------|
| **Activities (horizontal)** | Übergeordnete Nutzer-Aktivitäten als narrative Abfolge |
| **Tasks (vertikal)** | Aufgaben innerhalb einer Aktivität — Details unter der Aktivität |
| **Walking Skeleton** | Minimale End-to-End-Funktionalität — dünner horizontaler Schnitt |
| **Release Slices** | Horizontale Schnitte durch die Map = Release-Planung |
| **Stories as Placeholders** | "Platzhalter für Gespräche" — nicht vollständige Spezifikation |

**Kernaussage:** Backlogs sind flach und verlieren den Zusammenhang. Story Maps erzählen eine Geschichte.

## Wann einsetzen

- Neue Produkte oder Major Features planen
- Unübersichtliche Backlogs strukturieren
- Inkrementelle Delivery planen (was ist Release 1, was Release 2?)
- Produktvision für alle Stakeholder kommunizieren
